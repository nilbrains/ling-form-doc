# 2026-09-11

## ling-doc-plus 首轮优化（P0 + 部分 P1）

项目背景：Vue3 + Vite7 + Element Plus + Pinia 的 A4 表单文档设计器，被宿主以 iframe 嵌入（`#LING_DOC_APP`），对外暴露 `window.LingApp`（init / loadComponents / saveComponents / loadData / saveData / clearData）。设计态数据持久化到 localStorage 的 `ling-comps`；组件布局用 31 列 grid，`span` 格式为 `auto / a / auto / b`。

已改动：

- `src/App.vue`：修复防抖失效（`autoSaveDebounced` 提升到 setup 顶层创建一次）；新增统一 `persist()`，替换掉 12 处重复的 `localStorageUse.value && localStorage.setItem(...)`；`MODS.setshowed` 由误调的 `setRequired` 改回 `setShowed`；`Ctrl+↑/↓` 快捷键增加空值保护并改用 `persist()`；按钮 `v-for` 补 `:key`。
- `src/store/comps.js`：新增 `findItem()`；`setValue / setRequired / setShowed / setSubValue` 增加找不到时的提前返回，避免 `components.value[-1].x` 抛错；`chengeItem` 改为 `Object.assign` 字段级合并，保留对象引用以避免子组件整体重渲染 / 输入框失焦。
- `src/components/CompCheck.vue` / `CompRadio.vue`：去掉 `document.querySelectorAll` 取值，改为数据驱动（click 直接算出新值）；`props.value` 兼容 Array 与非字符串。
- `src/components/mitt.js`：`listenerDataChange` 返回注销函数；`removeDataListener(handler)` 支持精确解绑；`CompSelect.vue` 在 `onUnmounted` 注销自身监听，修掉多实例互相干扰 / 监听泄漏。
- `src/utils/LingApp.js`：`loadData` 取值由 `datas[it]` 修正为 `datas[label || id]`，与 `saveData` 口径一致；`optionCheck` 判定加类型保护。
- `src/components/Setting.vue`：`loadConfig` 不再假定正则一定匹配，span 兜底为 `[1, 25]`；`settingId` 赋 `?? ""`。
- 清理：`index.html` 标题改为 `Ling Doc Plus`；`src/main.js` 去掉多余空行。

验证：`pnpm build` 通过（7.87s，主 chunk 约 445 kB / gzip 152 kB）。

待办（用户尚未确认）：

- `vite.config.js` 同时装了 sass 与 less，但 `css.preprocessorOptions` 配的是 scss，项目实际全用 less，该配置无效。
- `base: "/ling-doc/"` 仍被注释，而 `outDir` 是 `dist/ling-doc`，宿主按子路径部署时资源会 404。
- 死代码 `src/utils/dict.js`（`getDictVal` 无引用）、死依赖 `json-editor-vue`、`codeflask`（`CodePanel.vue` 只是裸 textarea）。
- `index.html` 硬编码 localhost 接口地址，iframe 场景下应由宿主注入。
- 未做 `build.rollupOptions.output.manualChunks` 分包；无 ESLint / 类型声明。

## 第二轮（继续）

- `vite.config.js`：改为函数式 `defineConfig(({ mode }) => ...)` + `loadEnv`，`base` 支持 `VITE_BASE` 环境变量（默认 `/`）；删除无效的 `css.preprocessorOptions.scss`（项目全用 less，仓库内无任何 `.scss` 文件）。
- `package.json`：移除三个无引用依赖 `codeflask`、`json-editor-vue`、`sass`。注意：本机 `pnpm remove` 被 safe-delete 保护拦截（node_modules 批量删除失败），因此改为手改 package.json + `pnpm install --lockfile-only` 同步 lockfile；node_modules 里的冗余包需用户本地重跑 `pnpm install` 清理。
- 删除死代码 `src/utils/dict.js`；`CodePanel.vue` 清理无效的 codeflask 样式与空 hook（它实际只是裸 textarea）。
- 接口地址支持宿主注入：`LingApp.init({ dictUrl, dictAllUrl })` 写入 `window.config` 且不污染表单配置（用 rest 解构分离）；`index.html` 改为 `Object.assign(默认值, window.config)` 兜底；`App.genSelectOptions` 与 `CompSelect.loadData` 在未配置接口地址时直接跳过，避免误请求当前页面 URL。
- flatpickr 初始化从 `App.vue` 的 `genDaySelect()`（依赖 `setTimeout(..., 800)`，存在竞态）下沉到 `CompInput.vue`：组件内 watch `design` + `nextTick` 初始化，`onUnmounted` 调 `picker.destroy()`，并 watch `value` 同步外部回填，修掉重复实例与内存泄漏。

验证：`pnpm build` 通过（5.04s）。flatpickr 随 `CompInput` 拆成独立 chunk（52.9 kB），主 chunk 392 kB。

遗留建议（未做）：

- `Setting.vue` 仍是整个 config 的 deep watch 触发保存；因 `App.vue` 侧已有 500ms 防抖 + `chengeItem` 字段合并，收益有限且会改变实时保存行为，暂缓。
- 未做 `manualChunks` 分包；无 ESLint / `LingApp` 类型声明。
- `CompArea.vue` 与 `CompText.vue` 内容几乎一致，"地址选择"类型实际未实现。
- `components/comp.js` 的 `addXxxComp` 与 `components/custom.js` 的 `customs` 是两份重复的组件模板；`SIMPLE_PROPS` 里 `css` 定义了两次。

## 第三轮：设置面板 deep watch → 字段级提交

- `Setting.vue`：`config` 由 `ref({})` 改为 `reactive({})`（模板中的 `config.xxx` 写法无需改动）；用 `Object.keys(SIMPLE_PROPS)` 生成 `FIELD_KEYS`，逐字段 `watch(() => config[key], fn, { flush: "sync" })` 取代原来的整对象 `deep watch`。
- `Setting.vue`：新增 `suppressEmit` 标志，`loadConfig` 回填期间（先 `delete` 全部键再 `Object.assign`）屏蔽提交，避免回填被误判成用户修改；顺带修掉「切换组件时字段残留」（原来只做浅拷贝覆盖，不清空）。
- 提交载荷由整份 config 改为 `{ targetId, patch }`，patch 只含变化字段；`App.autoSaveItem` 适配为 `chengeItem(targetId, patch)`，更新真正落到字段级。
- 组件定位改为读 `componentStore.settingId`（Setting 内部不再维护 id 副本），App 侧在 patch 含 `id` 时同步 `settingId` —— 修复「面板里改组件ID 定位丢失 / 不生效」的 bug。
- 修复自定义样式不实时生效：原来 `@change="$emit('genStyle')"` 挂在 `el-form-item` 上（ElFormItem 没有 change 事件，属死代码），改为在 `autoSaveDebounced` 里检测 `patch.css !== undefined` 时调 `genStyle()`；同时移除 Setting 的 `genStyle` emit 与 App 的 `@gen-style` 绑定。
- 副作用（正向）：右键菜单「组件布局」`changeWidth` 现在能真正生效 —— `getConfig()` 返回 reactive 对象，直接赋 `comp.span` 会触发 sync watch → save → `chengeItem`。

验证：`pnpm build` 通过（4.88s，主 chunk 392 kB），lint 干净。

## 第四轮：消除组件模板重复

- `custom.js` 修正三个 key 的语义错位（原来 `N_CHECK` 是 SELECT「选择框」、`N_RADIO` 是 CHECK「多选」、`N_SELECT` 是 RADIO「单选」），改为 `N_SELECT`→SELECT、`N_CHECK`→CHECK、`N_RADIO`→RADIO；面板显示顺序不变（只换 key 不换位置）。
- `comp.js` 删除 5 个与 `custom.js` 的 `customs` 完全重复的 `addXxxComp`（-67 行），改为 `addCustomComp(key, comps, cb)` 复用 `customs[key].comp()`；`COMP_FUN_MAP` 的 `ADD_*` 相应变成薄封装；删掉空实现的 `ADD_SELECT2`。
- `comp.js` 的 `SIMPLE_PROPS` 里 `css` 原本定义两次（后者静默覆盖前者），删掉重复项。
- 删除 `CompArea.vue`：与 `CompText.vue` 逐字节相同，且 `type: "AREA"` 在全项目从未被创建（「地址选择」实际由 `group.js` 的 `areaJSON()` 生成一组 SELECT 联动实现）。`COMP_MAP` 移除 `AREA`，模板改为 `COMP_MAP[item.type] || COMP_MAP.TEXT` 兜底，未知/历史类型不再渲染崩溃。

验证：`pnpm build` 通过（4.88s，1540 modules，CompArea chunk 消失，主 chunk 391 kB），lint 干净。

## 第五轮：布局预设与选项解析去重

- `comp.js` 新增导出 `WIDTH_PRESETS`（`{ name, span: [start, end] }`），并由此用 `Object.fromEntries` 生成 `widthCommands` 注入 `COMP_FUN_MAP`，删掉 `changeWidth()` 与 10 个 `CHANGE_WIDTH_*` 手写条目。
- `App.vue` 的 `RIGHT_MENU.CHANGE_WIDTH` 改为 `Object.entries(WIDTH_PRESETS).map(...)` 生成 —— 右键菜单展示名与执行逻辑现在是同一份数据，改预设只需动一处。菜单顺序与原顺序完全一致。
- `comp.js` 新增导出 `parseOptionCheck(optionCheck)` 与 `parseOptionInput(label)`（原 `genInput` 改名并上收），替换 `CompSelect` / `CompCheck` / `CompRadio` 三处重复的 `optionCheck.split(/\n/)` 解析与两份重复的 `genInput`。
- `parseOptionCheck` 用 `/\r?\n/` 分行（原实现只按 `\n`），从 Windows 粘贴的 CRLF 选项串也能正确解析。返回值统一为 `{ value, label }`，CompSelect 再映射为 `field_name/field_value`。

验证：`pnpm build` 通过（5.00s，1540 modules）。CompRadio 2.13→1.91 kB、CompCheck 2.22→1.99 kB（共用解析逻辑后缩小），主 chunk 391 kB，lint 干净。

行数账：comp.js 净 +31、App.vue −10、三个组件合计约 −38，整体略减；主要收益是消除了 App.vue 与 comp.js 两份重复的布局菜单定义。
